# 正式写作阶段
先沿用或询问：学位论文还是期刊论文。学位论文优先用户/学校标准；没有其他要求时使用随包可替换的文字排版预设，适用边界在对应参考中。期刊论文确认目标期刊并核对官方指南/模板，收集约10—20篇相关论文的论证与图表样本，区分官方要求、样本观察与建议。
先形成主张—证据对应，再写章节；公式、数字、图表、代码与结果一致。真实数据、文献报告、计划和待验证结论分别写。生成Word等交付时用当前文档工具渲染检查；仅输出正文不声称版面验收。未附规范请由宿主读取或用户提供，不能凭空认证。

## 摘要写作与修改

用于摘要起草、压缩、润色及多轮修改。沿用已有材料、目标读者、篇幅和术语决定；期刊或学校的明确要求优先。下列是判断标准，不规定统一句数、字数比例或必须使用的连接词。

### 组织内容

- 以具体研究问题进入，说明研究对象、场景和已有方法在相关条件下的不足，压缩泛泛背景。优化类研究应让读者直接看到“针对什么问题、改进了什么”；交代基础方法及其归属，但不让基础方法介绍取代本研究的工作。
- 方法部分按需要展开主要改进，形成“改进对象—采取的动作—直接作用”的联系。作用尚未单独验证时写作设计目的，不把机制解释当作已证明的效果。采用现成模型、软件或排序工具与自身改进分开说明，工具名称本身不作为创新依据。
- 用已核实的数据或材料、比较条件、评价指标和关键结果回应研究目标。例如声称改善检索效果，应有相应命中或覆盖证据；声称降低开销，应报告实际测量的资源指标，不能用名义上限代替实际用量。
- 结论概括上述结果支持的贡献，保留会改变结论含义的适用条件。没有结果时明确缺项或给带占位的草稿，不补造数字，不把局部优势扩大成所有条件下领先。摘要结构随实证、理论等研究类型调整，不强加不适用的实验段落。

### 解释到读者能够理解

- 按目标读者检查关键术语。影响理解的自定义名称、缩写、状态和资源限制，在首次出现或紧邻位置用短语解释；英文缩写的展开遵循目标规范。对跨领域读者，优先使用具体可观察的描述，不用另一个未解释的术语替代原词，也不把所有正文定义搬进摘要。
- 交代判断对象与判断含义。“检测通过的对象”“有效候选”等称呼应指向前文说明的对象和条件；“可扩展”等关键状态应说明能够继续做什么。不能让读者猜测“检测通过”是否等同于前文的某个状态，也不能把“尚未确认”改写成“不存在”。
- 动作要有明确去向。“重新组合数据”“协调读取”等表述，需说明处理什么、得到什么或怎样改变后续处理。解释到足以理解该改进即可，公式、循环细节、完整约束和实现参数留在正文。
- 同一对象使用同一名称，沿用用户已经确认的术语。压缩、改写时不新增无必要的同义标签；同一术语、代词和状态名在摘要内保持一致。忠实保留数值、单位、比较方向、实现状态与必要条件。

### 表达示例

以下只示范语言，不代表已实现功能或实测结论；仅在源材料支持相应含义时采用。

| 含义不清的表达 | 交代清楚后的表达 |
| --- | --- |
| 设置读取额度 | 限定本次任务允许读取的记录总条数 |
| 优先保留检测通过的路径 | 优先保留已确认能够继续扩展的路径；前文需已说明扩展条件 |
| 重新组合已获取的记录 | 重新组合已获取的记录，生成此前未发现且满足约束的路径 |
| 优化读取协调 | 复用已保存的记录，减少重复读取；需与实际实现一致 |

这些领域示例不要求其他研究采用“路径”“读取额度”等概念，也不固定任何阈值或算法机制。

### 多轮修改与交付

- 每轮保留已确认的事实、术语、读者定位及表达要求，只修正当前问题及其必要关联。用户指出“啰嗦”时压缩重复解释；指出“看不懂”时补足关键对象、条件或结果，不靠不断增加新名词解决。
- 除非用户只要求局部替换或明确提出其他形式，交付一版完整、可直接替换的摘要，避免把修改散落成多个片段。事实缺项和必要说明放在摘要之外；是否修改文档沿用用户授权，预览请求不自动扩大为文档编辑。
- 交付前从目标读者角度核查：能否看出具体贡献；关键术语和指代是否明确；主要动作是否说明对象与结果；结果是否回应研究目标；改写是否改变事实或夸大证据。此核查不等于已完成原文、代码或数据验证。

## 引言写作与修改

用于建立研究动机、组织引言中的相关工作、引出研究缺口和主要工作。沿用已确认的核心问题、术语和结构，不把引言写成摘要的扩写或方法流程的提前复述。段数、篇幅及是否单列贡献由目标规范和实际论证决定。

### 围绕问题建立主线

- 开头交代读者理解核心问题所需的对象、任务与场景；压缩不能推进论证的泛泛背景。可采用“具体问题及其成因—相关工作—尚待解决之处—本研究应对方式”的主线，不要求每篇论文使用相同开头。
- 将问题成因讲成可理解的关系：谁在什么过程中受到什么限制，这种限制怎样造成研究关注的后果。不能从“资源有限”直接跳到方法名，省略中间的影响；没有证据的因果解释应保持为可能机制，不写成普遍事实。
- 指明关键对象与范围。账户、查询、信息、状态、容量、搜索范围等词不足以独立表达含义时，补充其所属对象、过程或计量内容。例如说明一次查询包含哪些活动、保存限制针对哪些记录；不以新增术语代替解释，也不把多类记录的保存上限误写成单一候选数量。
- 采用先综述后提出研究目标的结构时，开头集中交代问题及成因，在综述后的综合段集中说明本文要解决什么；避免前后多次重复同一目标或提前详细介绍全部改进。

### 用相关工作支撑研究缺口

- 按与核心问题的联系选择和组织文献，必要背景简要交代。相邻领域的文献可以提供机制借鉴，但不能因为都涉及同一应用领域，就占据与本文问题无直接联系的大段篇幅。
- 说明已有研究在什么任务或条件下做了什么、改善了什么，以及本研究条件下还需处理什么。按问题或方法联系组织段落，不逐篇堆砌题名，也不强行宣称所有引用都在解决本文完全相同的问题。
- 原方法、适用条件、作者报告的限制和本研究提出的进一步需求分别核实。端点、输入权限、信息获取方式或资源单位不同，可以构成适配需求，不能据此断言原方法在其自身任务中无效，或编造原作者没有报告的缺陷。
- 每段让具体方法和剩余问题承担过渡。能够直接承接上文时，从作者或方法的实际工作进入，删去重复且没有新增含义的引导语；不机械要求每段都以“围绕……”开头，也不将这一用词一概禁用。
- 文献综述以“做了什么—还需解决什么”推进，不反复用“评价目标不同”“不能直接等同”等比较声明代替具体研究缺口。影响动机成立的必要条件仍需简明交代，适配细节、公平比较协议和资源计量安排放到方法或实验的相应位置。

### 引出本研究与主要工作

- 综合段归纳由前文支持的未解决问题，并逐项连接本研究的应对方式。不要在“综上所述”后突然新增文献综述没有铺垫的核心问题，也不把研究目标、设计目的或任务定义自动称为已经证明的创新。
- 主要工作只保留理解贡献所需的改进及验证，不重复完整算法流程、参数清单或冗长实验安排。每项说明做了什么；重要机制可附简短目的，实测效果仍须有相应证据。采用现成工具与自身贡献分开，实验工作不冒充算法创新。
- 主要工作可以用精简列表，也可以并入综合段，沿用用户及目标规范的选择；不固定条目数，不因用户希望精简就丢失真正的核心贡献。段落之间承接已有问题，不用换一种说法重复上一段。

### 局部修改与核查

- 用户限定修改位置时，仅调整指定内容及保持指代、术语、编号一致所必需的关联处，保留其余已确认表达。需要扩大修改范围才能消除实质矛盾时，指出矛盾及建议，不借局部修订重写整段或全文。
- 预览与写入文档沿用当前授权；局部替换、完整引言等交付形式以用户本轮要求为准。保留已确认的版本和决定，不在后续修改中恢复已删去的表达或擅自增加问题、名词和贡献。
- 交付前检查：问题是否明确；约束到后果的联系是否讲清；文献是否与问题相关且归属准确；研究缺口是否由前文支持；改进是否对应缺口；主要工作是否精简；段落是否推进论证而非重复。原文缺失或主张未核实的情况另行说明，不以语言通顺代替证据核验。
