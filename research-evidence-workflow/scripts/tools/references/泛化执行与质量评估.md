# 泛化执行、统一证据与质量评估

使用者给出方向后，由执行者识别研究问题、证据形式和术语，选择合适来源并建立独立项目。下列配置属于内部工作记录，不要求使用者先选学科、填写命令或准备英文术语。暂不创建或安装Skill。

文献搜集的来源方式按[文献来源选择与上传接入](文献来源选择与上传接入.md)先沿用或确认；收到用户文献并整理后再决定是否补检。用户可以只有方向并选择自动检索，不要求其预先具备文献。

## 已有架构继续使用

通用核心管理来源、版本、问题、条件、证据、论断与决定；适配器处理旧库字段；项目实例保存实际编号、材料位置和研究约定。当前论文的银行、预算、窗口和种子不成为新项目默认。学位/期刊写作仍沿用既有分流与格式覆盖规则。

阶段按问题推进，可返回补证或有理由跳过。理论推导、测量、仿真、实证、文献综合可组合；登记验证路线不表示已完成证明、测量或实验。现有13阶段和旧状态文件保持兼容，不要求每个研究都有模型训练。声明路线变化时，已完成的下游设计、执行、取舍和写作进入待复核，历史版本保留。

```powershell
python research_flow.py route --state <项目>/research_state.json --mode theory --mode simulation --reason "依研究问题选择" --expected-evidence "完整假设、推导和有条件的仿真检查"
```

## 统一候选入口

`evidence_search.py`为已有完整语料、独立文献库和图谱提供同一查询/定位接口。原有工具及命令继续可用，未改动正式库。三个来源保留各自检索方式，分数不跨来源或跨问题比较。

```powershell
python evidence_search.py query --backend library --source <项目>/literature.json --root <项目> --question "具体问题" --terms "经核对的英文术语" --concept "中文概念|English alternative" --original-only --output <新的查询记录.json>
python evidence_search.py resolve --record <查询记录.json> --candidate <候选ID> --root <项目>
```

`corpus`使用完整语料manifest；当前项目仍按全部正式批次检索，`--alias`显式限定单篇。`library`使用项目文献登记；只有明确纳入的文献参与正文查询。`graph`使用明确来源根下的关系图，返回实体线索，不能被转换成原文证据。

统一输出包含来源及版本、文献身份、物理页、可用坐标、候选文字、证据类别、实际阅读状态与查询轨迹。`--original-only`只保留原文文本候选，元数据和继承笔记另有类别；它不认证内容支持。`--require-all-concepts`要求每组显式同义表达至少出现一个，约束范围仅为候选片段。未声明该选项时，概念词用于补充查询，不强称语义条件已经满足。

候选池默认500、上限2000，最终输出上限100；过滤后可能遗漏更后面的材料，返回截断提示。空结果只说明当前有界候选不足。重要结论应使用多轮有依据的查询并回查相关原页，不能把未命中解释成文献不存在。

未配置可选翻译器或嵌入模型时，纯中文问题对英文正文可能零命中；由执行者在问题分析时准备双语术语/概念并保留理由和来源，不向用户转移配置工作。图谱、中文补检及双语词项都不能自动核验否定、因果或支持关系。

## 阅读记录和条件关系

`evidence_quality.py`检查明确的选定页阅读记录，可在原图基础上另存补证版本：

```powershell
python evidence_quality.py --reviews <选定页阅读.json> --root <项目>
python evidence_quality.py --reviews <选定页阅读.json> --root <项目> --graph <原图.json> --output <新图.json>
```

记录采用`research-scoped-reading/1.0`，至少包含问题、机制、条件、验证、结果、局限和适配位置；每项写明已记录、未知或不适用及原因。关联可回放查询候选、原件SHA、页检查、原页预览及实际阅读范围。记录人的身份和是否独立复核必须明确。

程序检查来源绑定和声明完整性，不能证明读者理解正确，也不能从“已看预览”声明独立认证视觉判断。机器文本没有乱码也可能遗漏公式符号。关键公式、图注和表格必须回看原页；不以字符质量通过认证数学推导。

支持、挑战和证据不足分别处理；证据不足不生成支持关系。未知机制不建立为已知方法。现有文献/方法状态不提升为整篇精读或已采用，新增关系仅代表指定范围的阅读判断；单人复核与独立专家审阅不得混称。

## 两类验收分别报告

1. 工具行为：来源变化、版本绑定、路径边界、候选回放、缺原文、条件约束、路线修订和迁移恢复。
2. 研究任务：检索覆盖、具体证据相关性、引用是否支持、适用条件是否保留、证据不足能否识别，以及研究和写作结果。

检索质量评估应区分开发题、回归题与未用于改进的独立题。记录数据来源、出题方式、关键词是否已暴露、页级参考与完整相关性标注的边界；不能把参考页命中直接称为穷尽召回或科研泛化认证。

保留结果后不针对该批题继续调代码；下一轮改进应保留旧结果并加入新的未用于设计的题目。没有原文或任务证据时允许报告不足；候选数量不能替代质量判断。

## 版本、依赖与迁移

继续使用原来源版本和独立状态。新项目不自动合并到旧正式文献库；预印本/正式版和同名材料先核对版本关系。交接包需包含所用原文、登记、索引、查询、阅读、检查与图谱依赖；只有元数据的包须明确缺件。保存可移植路径与依赖说明，不把本机解释器盘符写入通用模块。

元数据与已保存候选检索使用标准库；重新解析/渲染PDF需要可用的解析器/渲染器。Windows OCR仍是可选本地能力，没有对应环境时保留待核。迁移验收应在新目录调用包内工具定位和检查来源；同机移动目录验收不等于其他系统和所有Python版本均验证。
