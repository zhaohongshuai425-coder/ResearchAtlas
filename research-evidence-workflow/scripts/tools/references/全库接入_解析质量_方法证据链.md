# 全库接入、复杂原文检查与方法证据链

本轮优先落实三项：原有正式全库接入、原文质量检查与按需离线识别、方法—问题—条件—证据—决策关系。按项目当前阶段接入，不改写已冻结实验。

## 1. 从已有全库开始

`corpus_tools.py`读取通用的显式来源清单，`adapter_v21_corpus.py`负责当前旧库字段映射。适配保留全部正式登记，不因缺原文、相关性低或尚未精读而删除；保留原编号、批次、原文/补充版本、阅读来源及原来的限制。

每个项目显式提供自己的语料清单、来源根目录及方法复核队列，核心不固定文献数、编号、学科或训练参数。

```powershell
python literature_tools.py corpus-search --manifest <语料manifest.json> --question "具体问题" --terms "对应英文术语" --output <新的查询记录.json>
python corpus_tools.py status --manifest <语料manifest.json>
```

默认搜索清单中的全部正式批次；`--alias`只在明确限定一篇时使用。元数据、继承阅读记录、PDF机器文本分别标记，缺原文记录只能提供登记线索。查询词与分数不认证语义支持。

中文问题先按原始查询词检索；原始查询完全无匹配时，对较长的连续中文片段生成有限的二字、三字片段进行补检。查询记录保留`declared_terms`、实际`retrieval_terms`和`query_expansion`，便于检查候选从何而来。已有匹配的显式关键词检索沿用原行为，限定文献的补检仍受`--alias`约束。此机制只补足中文词面召回，不自动翻译英文原文，也不保证候选语义相关；需要精确定位时仍应补充准确的中英文术语并回查原文。

本轮使用独立派生目录保存索引，原PDF仅引用、不复制。正式登记、旧SQLite、旧图谱及提取缓存保留。文件可用性按当前原件SHA检查，阅读状态按既有登记继承；方法登记里的旧训练状态不作为当前训练结论，实际结果须查现有实验档案。

批量机器提取支持pdfplumber文本框解析及可选PDFium原生文本后端；复杂矢量排版过慢时可显式切换。每份缓存记录实际引擎、版本和复用来源，不把两后端的文本次序或公式视为已经等价。PDFium正文缓存没有块坐标，精确阅读仍用选定页检查和原页预览。中途完成的缓存按原文SHA核对后可复用，未完成目录不作为已验收全库入口。

登记、缓存或原文发生变化时，旧绑定要复核，生成新的派生版本；不静默混用新元数据和旧正文。未实现自动合并预印本/正式版或跨项目去重，同名和同SHA仅作为复核线索。

构建索引先写入输出目录中的私有临时目录，全部写入并关闭SQLite后，再通过同一文件系统的硬链接发布到最终文件名。正常异常处理会清理本次临时文件，失败不留下最终半成品；修复来源问题后可在同一尚未存在的目标路径重试。已有目标文件、构建期间其他进程先写入的目标文件均保留并报错。文件系统不支持硬链接时明确失败，不降级为可能覆盖已有文件的写入；进程被强制结束可能留下临时目录，但不会将未完成索引发布为最终文件。旧版曾留下的目标文件须先核对来源或另选新输出路径，本次不自动删除。

## 2. 检查复杂原文

```powershell
python literature_tools.py inspect-pdf --pdf <原文.pdf> --pages 3 4 --expected-script cjk --tables --output <新的检查.json>
```

检查使用PDF物理页码，保留原件SHA、文本框坐标、图像对象、字符覆盖回退和选定页文本。表格检测结果只是候选网格；文本提及图/表/式、双栏迹象都会提示回看原页，不能自动转成真实统计数据、正确公式或确定阅读顺序。

乱码检查包括替换字符、私用区字符和在明确中文材料中异常占优的其他文字区间。语言预期未知时，不因合法外文字符自行拒绝；检测是有范围的启发式，存在漏报与误报。空白页、纯图片和字体映射错误分别列待核项，不把它们全称为扫描件。

少于40个非空白字符的页面也暂缓参与默认正文检索，避免仅提取页脚的图片页被当成完整正文；短标题页可能因此被误报，元数据和显式带警告查看入口仍保留。质量标记不自动推翻既有人工审阅记录，只约束本轮机器文本的使用。

新全文索引仍只属于机器提取。明显异常页默认暂缓参与正文检索；需要查问题时可显式`--include-flagged`查看带警告的内容。人工核对来源和条件之后，才可将其关联到论断。

## 3. 按需离线OCR

```powershell
python literature_tools.py ocr-pdf --pdf <原文.pdf> --pages 10 --language zh-Hans-CN --output <新的OCR旁文件.json>
```

当前提供可选Windows本地识别后端，使用已安装的Windows PowerShell、OCR语言包及PDF渲染依赖。其他系统没有此后端时如实报告不可用，仍保留原文与待核项。工具不安装软件、不上传原文，也不更改机器的持久执行策略；启动本地辅助脚本的策略参数仅作用于该子进程。

每页保留渲染参数、图像SHA、原文SHA、识别语言、词框及原始OCR文字。另存去除中文字符间识别空格的检索副本，不改写原始OCR输出。当前后端不提供置信度，字段明确为不可用；不能自造置信分数。

结果标记`OCR_CANDIDATE_NOT_VERIFIED`，不自动写回原文、原机器文本、正式书目或支持关系。目录、图中的箭头、公式、表格数值与多栏顺序仍须看原页。失败与超时保留，输出文件已存在时拒绝覆盖。

接口依据：[Microsoft OcrEngine.RecognizeAsync](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.recognizeasync)。本轮直接调用现有本机能力，不代表所有接收电脑均有该语言包。

## 4. 方法关系怎样深化

```powershell
python review_workbench.py queue --graph <原图谱.json> --root <明确来源根目录> --output <新的方法复核队列.json>
python review_workbench.py apply --graph <原图谱.json> --reviews <已核对的选定页审阅.json> --root <来源根目录> --output <新图谱.json>
```

`queue`整理原图已有的所有方法、来源、适用性、限制及证据入口，未知项保持未知。输出复核问题，避免仅增加文献或片段节点。该动作没有重新阅读全部方法，也不修改历史采用状态。

`apply`需要实际审阅记录：研究问题、方法原文、准确物理页/小节、输入和监督条件、局限、支持或挑战的论断，以及本次证据处理决定。检查原图版本、文献与方法归属、原文和选定页检查的SHA、页码和质量状态后，另存“方法—问题—条件—证据—论断—决策”链。

当前工具中的决定限定为证据范围判断，不接受直接替换/采用模型。新增支持关系只表示选定原文支持有条件的文献陈述；科学支持是否恰当仍由实际阅读核对。被挑战推断明确标记未采纳。继承节点和历史实验状态保持原样，原图不覆盖。

## 5. 本轮验收如何解释

真实当前库核对身份、原文版本和机器检索覆盖；对关键方法只重新核对指定页，未声称全库重新精读。原文、索引、阅读、实现、运行、验证和采用状态继续独立。

本轮不开展新训练、不评分Test、不替换论文模型；主要科研结论仍按原实验档案。全流程至正式论文、跨方向效果、语义检索和自动公式/表格理解仍需另外验证，不由本轮工具检查推定完成。
