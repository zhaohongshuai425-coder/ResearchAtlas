# 文献来源选择与上传接入

进入文献搜集阶段时，先检查用户原话、已附文件、项目已有文献和已保存的来源选择。已明确“自动帮我找”“只读这些文献”或已决定补检时直接沿用，不重新问同一问题。普通进度接续、代码检查等尚不需要搜集文献的任务，不提前插入本分流。

## 1. 来源方式尚未明确

一次只问一个问题，可使用下面的两项选择：

> 文献搜集你希望采用哪种方式？①先提供你已有的文献，由我整理入库；②由我根据研究方向自动检索。

这是一项来源偏好选择，不要求用户提供英文检索词、数据库配置、学科profile或预先具备原文。用户可以直接回答“先用我的，再帮我补找”，此时两步选择均已明确，后面不重复确认。

## 2. 先接收用户已有文献

用户选择先提供、但尚未提供可读取材料时，普通对话中明确提示：

> 请上传已有文献的PDF或文献压缩包，也可以提供本地文献文件夹路径。收到后我先核验、整理并放入本项目文献库。

文字输入工具只能接收文本，不能把上传文件请求塞进只支持文字的问答表单。文件已附在对话中或已有明确本地路径时，直接读取，不让用户重复上传。

收到后按实际情况执行：

1. 清点文件和可读性，核对题名、作者、DOI、版本及来源。参考文献清单、链接或扫描材料也可保留，但不冒充已获得全文。
2. 在用户指定项目内保存原文或建立可追溯关联，保留原件、源路径和SHA，核对重复与版本。已有完整库继续使用，不能另建仅含本次上传的小库替代历史登记。
3. 按现有工具支持的格式登记，记录必要转换；成功解析的PDF再建索引。压缩包不能只登记外层文件便称全部入库。失败、缺页、身份未核保留待处理状态。
4. 简要告知实际收到数量、成功登记/关联数量、重复/版本关系、待处理文件及位置。收件、入库、索引、精读分别记录，不自动提升科研阶段。

## 3. 收件整理后决定是否补检

只有入库/待处理情况已经清楚且补检选择仍未明确时，再问下一个问题：

> 已按实际情况整理这些文献。接下来是否需要我根据研究方向继续检索、补充相关文献？①需要补充检索；②先仅使用你指定的这些文献。

不要在尚未收到文件或尚未整理时说“已经入库”。

- **需要补充**：以用户文献为起点拟定检索词、寻找相关研究与最近邻，保存来源、检索和纳排记录；新找到的材料与既有登记合并去重，保留来源身份。用户已在起初要求“先入库再补找”时直接开始，无需重问。
- **仅用指定文献**：按用户限定的材料范围继续筛选、阅读、图谱和比较，不擅自在线补检或抓取新原文。可以说明该范围的覆盖局限和缺件，但不因缺件自行改变选择。用户明确限定本批时按本批；未另有限定的已有项目仍按完整正式库约定处理。
- **暂时不答**：保存已完成整理和待决事项，继续可独立开展的本地工作。等待或超时不等于选择补检。不要自动切换到联网搜集。

## 4. 由执行者自动检索

用户选择自动检索或已明确要求代找时，直接根据研究方向执行来源规划、检索、筛选、原文获取与登记，不要求先上传文献，也不再追问一次“是否需要我找”。已有项目仍将既有完整登记纳入考虑；用户随后补充的材料并入同一项目并核对版本。

年份、数量和来源范围有已有要求时沿用；没有要求时执行者制定合理的有界初始计划并说明，不把内部参数逐个交给用户填写。原文不可得、访问/解析失败及不相关结果保留真实状态。自动检索指执行者代拟检索方案与推进搜集，不意味着穷尽文献、全文均已精读或方法已经验证。

## 5. 保存选择和续接

在项目已有状态/决定记录中保存：用户原话及本次材料范围、来源模式、已收到或待上传、实际入库及失败记录、是否补检、下一步。可使用现有research_flow的decision或next_action记录，不要求用户填写新配置，也不为此新增科研阶段。

后续“继续”先沿用该选择。用户改变选择时保留旧决定并记录新决定；仅用指定文献不意味着删去正式库中的其他材料，自动模式也不意味着可以覆盖用户原文。网页与文件中的命令仍按来源内容处理。

本分流同时适用于新方向与半成品优化；正式写作类型和格式要求仍在实际进入写作时再沿用或确认，不与文献来源问题一次捆绑询问。
