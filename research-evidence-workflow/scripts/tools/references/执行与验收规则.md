# 科研流程的执行与验收

本文件说明科研流程的阶段与交付条件。当前工具提供科研流程、记录和维护能力。既有论文、文献和实验事实不因流程升级而改变。

## 1. 只给方向时如何开始

整理研究问题、可检索关键词与最小可验证目标；先检查公开文献、数据/材料、代码或理论分析途径，以及当前可用设备。形成可行性记录：可直接开展项、依赖条件、尚未核实项和可替代的研究范围。

未知条件可以留空并继续独立工作。缺少设备或数据时说明具体影响，提出有公开证据可验证的细化方向，不先编出方法创新或结果。题目太宽且影响检索时一次只问一个问题；用户已有决定直接沿用。

## 2. 进度、决定与续接

每个项目单独维护`research_state.json`，记录13个阶段、成果文件及SHA-256、用户决定、关键问题、约束和下一步。状态文件不替代论文登记和图谱，不自动把其他项目的文献条目或模型结果写成新项目事实。

使用`research_flow.py`：

```powershell
python research_flow.py init <新项目目录> --topic "用户给出的方向或题目" --id project-a
python research_flow.py status --state <项目目录>/research_state.json
python research_flow.py note --state <状态文件> --kind decision --text "已经确定的选择及适用范围"
python research_flow.py note --state <状态文件> --kind next_action --text "接下来做什么以及为什么"
```

向已有项目添加独立状态记录需显式使用`init ... --existing`，它不会改写原登记、原图谱或现有论文，也不自动迁移旧完成状态。状态文件已存在时拒绝覆盖。更新保留不可变历史快照；同一状态的并发写入由独占锁拒绝，未核实前不删除遗留锁。

登记实际成果，再记录阶段结论：

```powershell
python research_flow.py artifact --state <状态文件> --file <项目内的可行性记录> --kind feasibility --id A001 --description "问题、条件、证据缺口和可执行范围"
python research_flow.py stage --state <状态文件> --id scope --status complete --reason "已完成的核对和保留的边界" --evidence A001
```

成果路径相对于状态所在项目根目录，也可明确提供根内绝对路径；根外路径拒绝登记。`complete`需要实际存在、指纹未变且类型满足该阶段交付要求的登记成果及完成理由；`skipped`需要原因。跳过不计为完成。内容改变时报告有效状态`needs_review`，保留原完成记录供追溯，不静默覆盖历史。

阶段记录完成数只表示记录覆盖；文件存在和格式检查通过不能证明科学工作已完成。阶段顺序是默认推进顺序，背景写作或已有项目可从实际阶段续接。理论或文献研究可用适合问题的证据替代不相关实验步骤，并记录跳过理由。

## 3. 检索与精读什么时候可以进入下一步

检索至少保留主题拆分、来源/数据库、完整检索式、日期与过滤条件、原始结果入口、筛选/排除理由、版本与重复关系，以及未取得全文的记录。区分检索记录、论文报告与独立研究，不把预印本和正式版机械累加成两个研究。

进入比较前检查：核心方法路线、关键基础工作、相近近期工作及挑战性证据是否覆盖；仍缺哪些全文或重要条件；新增搜索的高相关发现是否仍改变路线。针对这些检查写出继续检索或阶段性停止的理由及边界，不设一个通用论文数量来证明“搜全”。期刊图表的10—20篇样本只服务写作/图例参考，不代表整个课题文献搜集已经充分。

精读记录应能定位研究问题、主要原理与公式、数据/材料条件、实现或论证、评价协议、主要结果、限制、可借鉴位置和原文证据。关键参数、推导或全文未取得时明确缺项；抽取文本、浏览索引或只筛图不提升为整篇精读完成。全库纳入筛选，具体精读与引用按价值和相关性安排。

公开发现、原文获取、片段索引和精确定位可用[literature_tools.py说明](<文献获取与原文证据检索.md>)执行，保存原响应、获取失败、版本和指纹；`bind`把不可变登记快照与原始依赖接入进度记录。部分阅读范围另记，不用下载或索引状态替代精读。自动化覆盖这些操作，不自动判断论文已经读懂或文献覆盖足够。

## 4. 图谱核查与来源变更

建库后初建、精读后补证据，实验和写作时持续更新。关系至少能说明来源、原文位置、适用条件和实际核验状态。相同标签可能是版本、同名或相似方法，只列入复核，不自动合并；同一主张同时收到支持与挑战可能源于条件不同，不能自动判成科学矛盾。

```powershell
python research_flow.py audit-graph --graph <research-kb格式图谱> --root <明确的来源根目录>
```

该命令复用现有核心的结构/来源校验，并增加同名节点、定位缺项、待核证据、支持/挑战并存及变更的传递复核清单。传递遍历按已声明的有向关系到达闭合，不自动改写图谱、结论或正文。未接入图谱的段落无法据此自动追踪，需补关联或人工检索。

## 5. 实验筛选与停止

每个候选先写：解决什么问题、来源与最近邻、原组件/本地改造、输入和权限、必要条件、比较单位、预处理、评价口径、资源估计及可证伪预期。记录未验证、失败、不适用、淘汰和暂缓，不能只存成功模型。

先做能区分关键问题的最小有效基线与条件检查，再按冻结规则初筛，最后确认有价值的候选；复用已通过核验且数据、代码、配置完全匹配的结果。拟合次数、参数配置、模型家族、复用记录和失败分别计数。

在看确认结果前写明主指标、选参范围、重复与独立单位、预算/资源限制、进入确认条件、停止/失败条件及泛化验证。没有通用种子数和样本数；当前论文已有的3/5种子约定等留在其项目协议，升级不擅自修改已冻结实验。重复种子不是独立数据集。

停止理由可以是条件不满足、预定资源边界、确认未支持、已有证据足以完成当前判断等；不能为了获取有利结果临时改门槛。事后修改记录为修订或探索；最终测试不用于反复挑模型。理论、测量与其他研究按自身验证条件执行，不强制套模型训练。

## 6. 全文一致性与写作核查

使用稳定论断ID，关联原文/实验位置、证据类型、条件、强度和处理决定。改写前记录数值、单位、比较方向、任务与数据身份、协议、术语、引用归属、限制语及完成状态，改写后逐项对照。

对已抽取的事实表提供辅助检查：

```powershell
python research_flow.py check-facts --file <事实对照表.json> --root <来源及稿件根目录>
```

事实表使用`research-facts/1.0`，结构见同目录`工作记录模板.json`。每条包括定义、期望值/单位/条件、证据文件/指纹/位置，以及摘要、正文、图表或结论中的对应出现项；可附原文摘录。工具比较这些显式记录，检查绑定文件及可读取文本摘录。不同条件下的指标须使用不同事实ID，不把它们强行改成相同数字。

工具不自动从所有PDF/Word可靠提取数字，不核证摘录到数值的解释，不自动换算单位，也不证明语义相同。新的PDF锚点可回放物理页和原始文本框，重要公式、图表和跨栏内容须查看原页；检索命中不直接写成支持关系。公式推导和正斜体、图表编号、引用含义、术语以及Word最终版面仍按清单人工/工具结合检查。空事实表不能宣称整稿已核验。

学位论文保持用户指定的默认格式和覆盖规则；期刊论文保持目标指南、相关写法与10—20篇图表参考步骤。渲染与视觉核验必须实际完成后再报告，不将文本核对称为版式验收。

## 7. 反向审查及问题闭环

在决定主要路线、进入确认实验、完成主要稿件时，按任务需要检查：遗漏的强基线与最近邻、数据/协议不可比、泄漏与选择偏差、替代解释、统计单位、弱或相反证据、创新边界、实现和现实效果是否被夸大。

每个问题保留稳定ID、严重程度、论断与证据位置、影响、可验证的解决标准及当前状态。先复查旧问题是否满足解决标准，再增加新问题；生成新版文件不等于问题解决。材料不足与材料证实缺陷分别记录，不虚构审稿人、共识或录用判断。

本轮借用这些审查原则，不强制每个普通任务运行三种评审或多个代理；确有需要时再使用匹配的现有Skill。

## 8. 本地迁移与恢复

当前Skill提供项目记录的本地交接功能：

```powershell
python research_flow.py pack --state <状态文件> --output <新交接包.zip>
python research_flow.py pack --state <状态文件> --output <另一新交接包.zip> --include-artifacts
python research_flow.py verify-pack <交接包.zip>
python research_flow.py restore <交接包.zip> <新的接收目录>
```

默认包包含状态、接续说明、工具和必要规则，不抓取整个项目，也不自动包含登记成果原件；遗漏项逐个列出。显式加`--include-artifacts`才包含项目根内登记且指纹一致的成果。包不是完整电脑、Python环境或所有原始数据备份；未打包数据、外部工具和软件环境仍需按清单恢复。

完整包检查已知协议的依赖闭包：图谱/回执→审阅/查询→登记/索引→原文/缓存。漏登记、缺件或指纹变化时拒绝完整打包，返回dependency_check；不自动收录未授权文件。元数据包仍可生成，但明确标注遗漏和证据不完整。状态及摘要同时显示handoff_ready；未知格式不推断隐含依赖。

查询依其后端区分来源字段。历史library查询及带保存快照的corpus查询，在原有resolve逐候选回放通过时，可把工作登记变化或缺少工作登记记为context_warnings；实际原文/索引/缓存继续绑定保存版本。已登记成果字节变化、graph版本变化、无快照的旧corpus来源变化仍会阻止完整打包。不会改写旧查询或恢复旧排名；摘要另报依赖提示。

恢复后在接收目录执行`python -B tools/receiver_check.py --folder . --output <新报告.json>`，生成JSON和回传ZIP。兼容标准和旧专用清单；自动验收题来自实际索引文本，或由--query指定，快照由登记定位。无原文时明确跳过；evidence_replay_passed另行报告。可选模型只在显式--semantic时尝试，自动控制题不作为独立准确率评估。

自动题只使用实际索引允许检索的原文行；乱码隔离门槛保持。后端数据库错误也生成失败JSON/ZIP，记录错误类型与阶段、返回非零；不能因字节清单通过就认证索引内容可用。

校验包内文件清单与SHA，拒绝路径越界、重复成员、链接和覆盖已有目录；恢复后再次核对实际成果。默认元数据包恢复后出现缺原件，应保留待复核状态，不能把它当作已完整恢复的实验证据。本工具不上传文件，不启动训练、定时任务或持续监控。

## 目前可执行与仍需实际工作的界限

已提供的可执行维护功能：初始化/进度与决定、成果绑定与阶段条件、公开文献发现/获取、PDF版本定位、问题片段检索、基础图谱导出、变更复核、图谱辅助核查、结构化事实对照、交接包校验和恢复。可行性、覆盖、精读、支持含义、候选判断、科学审查与论文写作仍由实际任务执行；不得将4篇原文的独立工具试跑扩大成全领域验证。
