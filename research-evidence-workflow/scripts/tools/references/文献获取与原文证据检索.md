# 从公开文献到可追溯的问题检索

本轮落实三项功能：公开文献发现/获取与入库衔接、原文位置锚点、围绕研究问题提取证据候选。使用同目录上级的`literature_tools.py`；工具本身不调用付费模型接口或启动训练。

## 最小输入与工作目录

最小研究输入仍可以只有方向或题目。进入搜集阶段先按[文献来源选择与上传接入](文献来源选择与上传接入.md)沿用或确认来源模式：先接收用户文献，整理后再决定是否补检；或由执行者直接自动检索。仅用指定材料时不擅自联网扩展。需要检索时由执行者生成检索词并保存来源和筛选理由；下列命令和JSON是内部接口，不要求用户先学会配置。

```powershell
python research_flow.py init <新项目目录> --topic "研究方向或题目" --id project-a
python literature_tools.py init --library <项目目录>/literature.json --topic "研究方向或题目" --id project-a
```

初始化不生成示例文献、阅读或实验事实。`literature.json`所在目录是本资料库明确的来源根目录；原始响应、PDF和文本索引都在其内保存。原文件保留SHA-256，元数据修改保留历史快照。

## 1. 发现、获取与筛选

```powershell
python literature_tools.py discover --library <登记文件> --query "依据方向制定的检索词" --limit 10
python literature_tools.py publication --library <登记文件> --url <出版方论文页面URL>
python literature_tools.py import --library <登记文件> --file <已核对的文献记录.json>
python literature_tools.py list --library <登记文件>
python literature_tools.py select --library <登记文件> --document <DOC编号> --status included --reason "与问题相关的具体原因"
python literature_tools.py fetch --library <登记文件> --document <DOC编号>
```

- `discover`当前接入Crossref公开REST元数据服务，保存原始响应、查询、日期和有界结果。它是发现入口之一，不代表多库检索或穷尽覆盖；完整课题仍由执行者选用适合的问题来源并保留其他搜索记录。
- `publication`读取实际网页的citation元数据，并保存原始HTML。网站不支持该元数据时记录失败，执行者可核验后显式导入记录，不猜造题名或DOI。
- `import`接收JSON数组或包含`records`数组的对象；每条至少有真实题名和DOI、来源URL或明确提供方ID。可保留作者、刊会、各类原始日期、公开PDF候选、代码/数据链接及核验说明。原始导入文件留存。
- 仅同一归一DOI或明确来源身份自动关联元数据报告；不同DOI即使题名相同也保留并列复核。预印本与正式版须核对关系，不自动认定独立研究或擅自合并。元数据来源有差异时保留不同报告和冲突标记。
- 新记录初始为`candidate`。执行者以理由标记`included`、`excluded`或`pending`，只有明确纳入的文献参与默认原文检索和图谱导出；其他状态继续登记在范围和缺口清单中。
- `fetch`可用`--url`指定已核验的公开原文地址，默认从已登记的各元数据报告汇集PDF候选。响应不是PDF、证书异常、超过字节预算或不可访问时保留失败；不绕过登录/付费墙或关闭TLS验证。可另找合法公开版本并记录来源与版本关系。
- 原文获取成功只改变可用性，不改变阅读、实现、运行或采用状态。网页相关链接只作为资源候选；代码是否作者维护、数据访问/许可是否适用仍需实际核验，不自动克隆执行。

默认单次发现至多100条、单PDF30 MiB；如任务确需更大文件可显式调整`--max-mb`。这些是工具资源边界，不是研究样本量、论文数量或学术充分性标准。

## 2. 原文索引与精确定位

```powershell
python literature_tools.py index --library <登记文件> --document <DOC编号>
python literature_tools.py locate --library <登记文件> --anchor <锚点编号>
python literature_tools.py render --library <登记文件> --anchor <锚点编号> --output <新的原页预览.png>
```

PDF解析优先用`pdfplumber`的文本框，保存物理页码、文本块、块内字符范围和矩形坐标；可退到`pypdf`，退化时坐标为空并保留后端信息。锚点包含文献ID、内容/解析版本标识、页码、块号和片段号，不把新版本静默映射到旧锚点。

解析会纳入PDF内部嵌套对象的文字，并将已提取的非空白字符与页面字符对象作覆盖检查；发现文本框只覆盖少量字时回退到整页文本、明确坐标为空。覆盖检查是提取完整性的线索，不保证阅读顺序、数学含义或所有不可见/图像内容正确。旧索引保留，图谱默认只导出当前索引，显式定位旧锚点时会标明它是否仍为当前版本。

每次定位与检索均核对原PDF及索引指纹。原文缺失、字节变化或索引损坏时不把缓存片段作为当前有效证据。库前置封面可能使PDF物理页码与论文印刷页码不同，工具默认只承诺物理页码；执行者回原页核查。

扫描或稀疏文字页列入OCR复核，不生成不存在的正文。图号、表号、公式号是文本提及候选，坐标是相应文本框，不保证是整幅图、整张表或完整公式的边界。复杂公式的变量、上下标和推导必须回原页阅读；不能把自动抽取称为数学验证或全文精读。

`render`输出源PDF页的栅格预览，保留原PDF，不生成替代论文图片。需要实际查看后才记录视觉核查完成。

## 3. 按研究问题检索与形成答复

```powershell
python literature_tools.py ask --library <登记文件> --question "要解决的具体问题" --terms "相关英文术语" --output <新的检索记录.json>
python literature_tools.py ask --library <登记文件> --plan <问题检索计划.json> --output <另一检索记录.json>
```

计划格式可为：`{"question":"实际研究问题","terms":["由执行者从问题和文献提取的术语"],"concepts":[["同一概念的中英文或同义写法"],["另一个需同时关注的概念"]]}`。只使用有依据的术语扩展，不要求用户提供这些字段；中文提问与英文原文之间的术语由执行者衔接。

现有检索实现为词项切分、声明的中英文概念扩展、BM25类排序与每文献候选数量限制。返回真实片段、原文路径/来源URL、物理页码、坐标、锚点与文件指纹。它不是嵌入语义模型、推理或自动支持度认证；检索分数不能解释为结论可信度。

形成答复时按此顺序执行：

1. 把问题拆成需要回答的要点，检索支持、限制及相反材料；原文不足的部分列缺口。
2. 通过`locate`及完整相关页回查，剔除只在参考文献或词面上相关的候选；补看上下文、条件和定义。
3. 由执行者据证据归纳回答，分别标注文献报告、本次分析与尚待验证内容；每项重要结论绑定核实过的锚点。
4. 保留问题、术语、候选及最终使用的证据。没有匹配全文时输出证据不足；仅元数据的文献不能被冒充全文依据。
5. 引用正确性、内容真实性、方法有效性及模型是否真正依赖该来源是不同问题。文件、锚点或文本支持检查不能自动认证其余层面。

独立脚本的`ask`只交付证据候选，明确返回`answer_generated=false`。当前执行者可以结合这些片段与原页撰写有据答复；本轮不引入后台问答服务或外部模型密钥。

## 4. 图谱与进度衔接

```powershell
python literature_tools.py graph --library <登记文件> --output <新的图谱版本.json>
python literature_tools.py bind --library <登记文件> --state <同项目的research_state.json>
```

`graph`为已纳入文献生成来源可核的文献、原文版本和文本证据候选关系，沿用`research-kb/1.0`。它不自动创建“支持”“挑战”或方法优劣关系，不提升精读状态；这些关系由精读与核验后补充并另存图谱版本。已有输出拒绝覆盖，避免丢失人工整理。

`bind`生成根目录内不可变的文献登记快照，登记原始响应、PDF和索引依赖；可重复执行并复用同一绑定，不登记易变的`literature.json`作为永久不变成果。之后用原`research_flow.py`按实际交付记录阶段依据。

原迁移工具使用`--include-artifacts`时可携带已登记的这些依赖和新工具。仅元数据包不能保证原文恢复，接收方仍需可用的可选PDF解析依赖；检索已保存索引不需要再次解析PDF。

## 依赖与来源

元数据获取、登记、索引读取、检索、锚点验证和图谱导出使用Python标准库及本地`core.py`、`research_flow.py`。PDF解析选用可用的`pdfplumber`或`pypdf`；原页渲染还需相应渲染器。记录实际解析器版本。当前主Python缺少解析包时使用已配置的工作区运行时，不硬编码这台电脑的解释器路径到共享工具，也不自动安装全套环境。

实现参照已核验的[Crossref官方REST说明](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)，并借鉴现有literature-review的检索留痕、记录/报告/研究区分与引用核对规则，以及PDF Skill的原页核查原则。无第三方训练器复制或实验效果继承。
