# 摘要读取与单次运行

普通状态接续先运行`research_brief.py status --state <项目/research_state.json>`。它仍核对全部登记成果的文件绑定，返回各阶段真实状态及缺件总数，默认只展开前10条缺件；省略数量显式列出。失败保持失败，不将精读、验证或采用状态提升。

查看图谱先用`research_brief.py graph --graph <图谱.json> --root <项目>`。返回完整图的节点、边、来源及类别统计，节点展示默认5条并提供next_offset；不会把全部节点payload和原文片段打印到上下文。需要某条关系的细节时按精确`--node`选节点；`--include-payload`也只提供1200字符预览，不能替代原文精读。来源SHA验证需显式`--verify-sources`；否则source_verification标为not_requested。摘要结构检查不证明科学有效性。

`research_brief.py library --library <登记.json>`用于分页查看元数据与阅读状态。总数以完整登记计算；显示一页不构成全库筛选完成，也不把未索引文献排除出考虑范围。原文内容问题继续使用检索、resolve、补读和实际阅读接口。保留历史、新增及以后正式纳入的全库范围。

输出默认上限16000字符，超限拒绝输出并提示减小--limit或选定节点。所有省略均保留计数或truncated标记，完整文件不改。精确数据解释及正式论断仍回到原文与冻结证据版本。

## 单次独立任务

当前会话直接推进工作时不调用嵌套模型。只有用户明确要求独立运行、行为测试或类似任务时，才使用`run_codex_task.py`：

```text
python run_codex_task.py --cwd <隔离目录> --prompt-file <明确任务.txt> --output <新结果目录>
```

它使用原生app-server stdio握手、thread/start或resume、turn/start和完成事件；只认同一thread和turn的真实完成状态，失败/中断/超时保持非成功。任务使用只读沙箱，遇到审批或交互输入不能自行同意或编造答案。默认沿用已有模型和连接；当前OpenAI账户因WebSocket失败而需要HTTPS时可显式加`--http-openai`，仅改变该进程配置，不复制凭据或更改全局设置。

收尾先退订本次thread再关闭stdin，等待原生进程正常退出。超时才清理本程序拥有的进程；强制清理、原生非零退出或交互缺项均使验收失败。`result.json`分开记录task_status、native_exit_code、forced_cleanup和runner_exit_code，不能把父脚本返回0当作原生退出正常。客户端不自动重发任务，没有定时监控或后续无限队列；原生连接自身的重试仍由Codex配置决定。
